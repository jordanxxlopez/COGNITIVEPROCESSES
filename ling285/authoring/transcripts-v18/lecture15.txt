2|The vowel network takes in two numbers, **F1** and **F2**. It gives back one response for each of five words, **done**, **dune**, **dean**, **Don** and **Dan**. >> The inputs are measurements of the sound. >> The outputs are the network’s responses to each word. || Between the inputs and outputs are three **hidden layers**. >> They hold three, two and four neurons. >> Each hidden neuron takes values from the layer before it and passes its result to the next layer. || Every layer is **fully connected**. >> Each neuron is wired to every neuron in the next layer. >> Each wire has its own **weight**. >> A weight sets how much the value on that wire counts. A positive weight keeps its sign, and a negative weight flips it. || F1 and F2 both feed every neuron in the first hidden layer. >> Each of those wires has a different weight. >> So each first-layer neuron mixes the same two formants in its own way. || Changing a formant and changing a weight are two different things. >> A new formant changes what travels along the wires. >> A new weight changes how much a wire counts. >> A weight is never the probability of a word.
3|**Forward propagation** carries the input through the network, one layer at a time. The example uses **F1 = 320** and **F2 = 2000**. || The first neuron multiplies each input by its weight and adds the results. >> Its weight for F1 is small and positive. Its weight for F2 is small and negative. >> F2’s negative part is larger, so the total comes out to **−0.40**. || Multiplying and then adding like this is called an **inner product**. >> The other neurons do the same thing with their own weights. >> A negative result is still an ordinary number that the next layer can use. || Each layer repeats this step on the results of the layer before it. >> The layers have to go in order, because each one needs the results of the last. || The final sums are called **logits**. They are scores, not probabilities. >> A step called **softmax** turns them into probabilities. >> Softmax makes every probability positive, and it makes them all add up to 1. || For this example, the network gives **done** the highest probability, about **56%**. >> It gives **dean** only about **8%**. >> These are just the network’s current guesses. They do not tell which word was really spoken.

6|**Backpropagation** is how a network learns. It starts by comparing the network’s answer with the right answer. || The network’s answer is its **computed output**. >> For the example, it favors **done**. >> It gives **dean** only about **8%**. || The right answer is the **desired output**. >> It marks **dean** as the correct word, because dean was the word that was spoken. >> So the network’s best guess and the right answer do not match. || A **loss** puts a number on how wrong the network is. >> The loss used here, **cross-entropy**, looks at the probability given to the true word. >> More probability on dean means a smaller loss. Less probability means a larger loss. || The calculation then works **backward**. >> It starts at the outputs and figures out how the last layer of weights caused the error. >> It uses that result to work out the layer before, and so on, back to the start. || A **gradient** tells how the loss would change if one weight changed a little. >> Each weight is then moved a small step in the direction that lowers the loss. >> A positive gradient makes the weight go down. A negative gradient makes it go up. || All the weights are updated together in one step. >> After the update, the network has to be run forward again to see its new answers.
7|The question is, **if this weight goes up, does the error go up or down?** The right word is **dean**, but the network favors **done**. So the real question is what the change does to dean’s probability. || One marked weight connects the last hidden layer directly to **done**. >> The weight is positive, and the value coming into it is positive. >> Raising this weight raises the score for done. >> The five probabilities share one total, so a higher score for done leaves less for dean. >> The error goes **up**, so this weight should come down. || Another marked weight sits at the very start, connecting **F1** to the first hidden layer. >> Raising it changes that first neuron’s value. >> That change then spreads through every later layer and reaches all five words. >> Looking at this one early weight is not enough to know which way the error will move. || Working backward through every layer gives the answer. >> For this example, raising the early weight also makes the error go up. >> So both weights should come down. >> The weight near the output was easy to judge. The early weight needed every path after it added together, and that adding up is what backpropagation does.
8|Why does training run **backward**? The answer comes from comparing the **last** weights with the **first** weights. || The **last weights** sit right next to the output. >> They set the output probabilities directly. >> So the error depends on them very directly. >> The gap between the network’s answer and the right answer shows right away how to improve them. || The **first weights** sit far from the output. >> They shape the first layer, which then passes through two more layers before reaching the output. >> It is hard to tell how much of the final mistake they caused. >> Their effect also includes the effect of the last weights, since the last weights come after them. || So fixing the last weights is the **easy** problem. >> Fixing the first weights depends on it. || A good way to handle problems like this is to solve the small ones first and then reuse their answers for the big ones. >> This method is called **dynamic programming**. >> **Backpropagation** is a form of dynamic programming. It works out the effects near the output first, saves them, and reuses them for each earlier layer. || In short, **backpropagation** combines two ideas. >> **SGD**, stochastic gradient descent, is the rule that adjusts each weight. >> Dynamic programming is what makes the gradients for SGD quick to compute.
9|To learn, the network needs many examples, each with the right answer attached. These are stored in two **training matrices**. || The first matrix holds the **inputs**. >> It has **110 rows**, one for each recording. >> Each row holds that recording’s **F1** and **F2**. || The second matrix holds the **right answers**. >> It also has 110 rows, one for each recording. >> It has five columns, one for each word. >> Each row puts a **1** under the correct word and a **0** under the other four. This is called a **one-hot** target. || For example, the recording with **F1 = 320** and **F2 = 2000** is marked as **dean**. >> This is the same example that went through the network. || The rows of the two matrices must stay lined up. >> Each row of formants must stay next to the right answer for that same recording. >> If they got out of order, the network would learn from the wrong answers. || The network’s guess and the right answer are kept separate. >> Before training, the network guesses **done** for the dean recording. >> The answer matrix still says **dean**. Training compares the two and moves the network toward the right answer.
10|One full step of training can be written in a short **PyTorch** program. It uses all **110 recordings** at once. || The program first loads the two matrices. >> **X** holds the formants for each recording. >> **Y** holds the right answer for each recording. || Then it builds the network, layer by layer, with **nn.Sequential**. >> The layers have the same sizes as the network in the picture. >> No sigmoid is used between the layers yet. || Then come the training lines. >> **SGD** is set up with a **learning rate of 0.1**. The learning rate sets how big each step is. >> **zero_grad** clears out any old gradients. >> The **loss** line runs the network on the data and measures how wrong it is. >> **backward** works out the gradient for every weight. >> **step** uses those gradients to change the weights. || Each of these lines does a separate job. >> Working out a gradient does not change a weight by itself. Only the step does that. || This program takes just **one** step, with no loop to repeat it. >> It also starts from PyTorch’s own random weights. So it has the same shape as the network in the picture, but not the same numbers.
11|The **sigmoid** function takes an inner product and turns it into a number between **0 and 1**. Its formula is **σ(z) = 1 / (1 + exp(−z))**. || Big numbers get pushed close to the ends. >> If the inner product is **large and positive**, the sigmoid is close to **1**. >> If it is **large and negative**, the sigmoid is close to **0**. >> For example, an input of **4** gives about **0.98**, and an input of **−4** gives about **0.02**. || The sigmoid has an S shape. >> It is steep in the middle. A small change there makes a big change in the output. >> It is flat at both ends. A big change there makes only a small change in the output. || The idea comes from biology. >> **Lord Edgar Adrian** won the **Nobel Prize** in 1932 for work on nerve cells. >> In his view, **neurons are nearly digital**, either on or off, roughly. >> The sigmoid captures this. It acts almost like an on-off switch at its ends, but it changes smoothly in the middle. || **Animal perception** works in a similar way. >> Some things that seem alike are perceived as different. >> Some things that are very different are perceived as the same. >> The sigmoid does the same thing. Two inputs on either side of the steep middle come out very different, while two inputs far out on one end come out almost the same.
12|Sigmoid can be added to the network **one neuron at a time**. The input stays the same, and the weights stay the same. || When the first neuron switches to sigmoid, its output changes from **−0.40** to about **0.40**. >> That new value changes what every later neuron receives. >> So every later value has to be worked out again, all the way to the output. >> Adding sigmoid to one neuron changes the whole rest of the network. || The process continues until every hidden neuron uses sigmoid. >> Each hidden value is now squeezed between 0 and 1. || The output still uses **softmax** to turn scores into probabilities. >> With sigmoid in every hidden neuron, the network now favors **Dan**, at about **32%**. >> **Dean** rises to about **23%**, up from about 8%. >> **Done** drops from first place to about 16%. || The input and the weights never changed. >> Only the activation rule changed, yet the network’s answers changed a lot. || This is not learning. >> Dean’s probability went up, but Dan is still the top guess. >> Adding sigmoid can change the network’s favorite word, but only training can teach it the right one.
13|The PyTorch program for the sigmoid network is the same as before, with one change. **nn.Sigmoid()** is added after each hidden layer. || Each hidden layer now does two things. >> First, it adds up its weighted inputs. >> Then it passes those sums through sigmoid before sending them on. || Sigmoid changes each value, but it does not change how many values there are. >> A layer that gives out three values still gives out three values after sigmoid. >> So each next layer still receives the right number of inputs. || The very last layer has **no** sigmoid after it. >> Its five scores go straight to the loss, which turns them into probabilities. >> The hidden sigmoids and the final probabilities do different jobs. No hidden neuron stands for a word. || The training lines are exactly the same. >> Clear the old gradients, run the network and measure the loss, work out the gradients, then take a step. >> The learning rate is still **0.1**, and all 110 recordings are used in the one step. || The program starts from PyTorch’s own random weights. >> So it has the same shape as the network in the picture. >> It would only give the same probabilities if it started from the same weights.
