3|**Every dynamical system can be described by three things**, which are its **elements**, the **relations** between those elements, and the **goal** the whole system is working toward. >> This simple lens works for animals, for people, for machines and for learning algorithms alike. >> Asking what the parts are, how they affect each other and what the system is trying to reach is the first step in understanding any of them.
4|An **octopus** defending its den is a dynamical system. Its elements are its eight arms and the ground it pushes against. The relations between each arm, the ground and an approaching fish are planned by a nervous system that sits partly in its head and partly in the rest of its body. >> The goal of the whole system is to keep its den. >> All of the arms working together toward that one goal is what makes the behavior a single system rather than eight separate movements.
5|**Speaking is also a dynamical system.** Its elements are the many parts of the tongue, the lips, the velum, the larynx, the palate and the back wall of the throat, and the brain plans the relations between all of them. >> The goal of the whole system is to convey a thought to a listener. >> Just like the octopus arms, these parts have to be coordinated so that they all serve that one goal at the same time.
6|**People are full of dynamical systems.** Every voluntary action, and every involuntary action of the heart, the pancreas and the neurons, is a dynamical system, and its elements can be as big as organs or as small as cells and the chemicals inside them. Biology, chemistry and physics are all about dynamical systems, and the speech system is a very complex one. >> Because dynamical systems are everywhere, one system can be used to study another, since they share an underlying similarity despite looking extremely different. >> Seeing that very different things can be the same in this deep way is exactly the kind of thinking found at the top of Diotima's ladder.
7|The octopus example comes from real research analyzing a complex octopus action as a combination of simpler movement pieces. Studying how the octopus coordinates its arms to slap at a fish teaches something general about how a complex body achieves a goal. >> The same way of thinking carries straight over to the tongue, which is also a flexible, muscular structure with no bones. >> So studying one animal's dynamical system can shed light on how human speech is controlled.
8|**AI is a model of several animal psychological skills**, which are knowing, recognizing, attending, acting and learning. The cloze procedure links these skills to language, because filling in a missing word is a test of knowing. >> So the AI side of the course and the human side are studying the same abilities from two directions.
9|**In GPT, each word is a vector, a list of thousands of numbers**, and these input vectors are called x's or **tokens**. The system's knowledge about language is held in an enormous set of numbers called **weights**, or W's. The system mostly adds, subtracts, multiplies and divides to combine its weights with the vectors it is given. >> The result of those calculations is a probability distribution that amounts to the system's guess for the next word. >> How the weights combine with the input vectors is itself a dynamical system, but learning is an easier dynamical system to understand first.
10|**The weights start out completely random, so the system begins by faking it until it makes it.** The system is given a sequence such as chickens cackle and ducks, and it predicts the next word by combining its random weights with the input vectors. Since the next word should be quack, the system is told to change its weights so that its output looks more like the right answer. >> This is repeated with more and more sequences, billions of times, and each time the weights change a little to improve the guess. >> That is how large language models both learn and come to know things.
11|**AI learning rests on two tricks, faking it until you make it and learning by making mistakes.** The system starts out knowing nothing, with random weights, so at first it is just faking it. >> Each wrong guess gets feedback, and the weights change a little so that the next guess is better. >> After a huge number of these corrections, the system ends up with the right knowledge, which means it has made it.
12|Averaging a short list is easy by adding the numbers and dividing, but that direct method does not carry over to speech, language, molecules or scenes. So a learning method is built instead, which makes a wild guess about the average and then improves it by looking at the data. >> It looks at one number from the list, compares it with the current guess, and moves the guess a bit closer to that number. >> Then it repeats with another number, which is called **observation-based error learning**.
13|**Stochastic gradient descent starts with a wild guess.** The goal is to find the average, which is the essence of a list of numbers, but the algorithm begins by picking any random number as its first estimate. Here the first guess is far above the real average on purpose. >> The **learning rate** is set to one quarter, which means each step will move the guess a quarter of the way toward the number it is compared with.
14|**One observation creates an error.** A number is picked at random from the data and compared with the current guess, since the average ought to be close to the data. The difference between the guess and that data point is the mistake, which is called the **discrepancy** or the **loss**. >> Here the guess is well above the data point, so the loss is positive.
15|**The guess then moves a quarter of the way toward the observation.** A quarter of the loss is subtracted from the current guess, and because the loss was positive, subtracting it pulls the guess down toward the data point. >> The new guess is still too high, but it is closer than before.
16|**The same correction is repeated with a new random observation.** Another number is drawn from the data, the loss is found again, and a quarter of it is subtracted from the guess. >> Since the guess is still above the new data point, the guess moves down again.
17|Each repetition follows the same recipe of comparing, finding the loss and moving a quarter of the way. As long as the guess sits above the data points it sees, every step pulls it lower. >> The steps are not all the same size, because each one depends on how far the guess is from that particular data point.
18|After a few more corrections, the guess has come down a long way from its starting point. It is getting close to the region where the real data actually lies. >> Each step still moves it only part of the way, so it approaches the average gradually rather than jumping there.
19|**A high data point pulls the guess upward.** This time the randomly chosen number is above the current guess, so the loss comes out negative. Subtracting a negative amount actually adds to the guess, so the guess moves up toward that data point. >> This is the purpose of the minus sign in the update, since it moves the guess toward the data point whether that point is above or below the guess.
20|With the next observation, which is lower again, the guess moves back down. So the guess is now being pushed from both sides, by data points above it and data points below it. >> Being pulled in both directions is what keeps it hovering near the middle of the data.
21|The corrections keep coming, each one smaller when the guess happens to be near the data point and larger when it is far away. >> The guess is now in the right neighborhood, and the remaining steps mostly fine-tune it.
22|Another low data point pulls the guess down a little further. Over many steps, the high and low observations balance each other out. >> That balance point is exactly the average of the data.
23|Once again a data point above the guess produces a negative loss, and the minus sign turns that into a step upward. >> So the guess never runs away in one direction, because any data point on the other side of the guess pulls it back.
24|When a data point happens to be very close to the guess, the loss is tiny, so the guess barely moves. >> This is how the method naturally slows down once the guess is good, since nearby data produce only small corrections.
25|The guess keeps jittering by small amounts as new random data points arrive. >> Each step moves it toward whichever number was drawn, so its path is a little uneven.
26|After a dozen corrections, the guess has come down from its wild starting value to sit right around the true average of the list. >> No division of a total was ever done, since the guess got there only by learning from its mistakes one observation at a time.
27|**That is stochastic gradient descent**, and it has just two steps, which are making an initial guess and then using data to improve it. **Stochastic** means each observation is picked at random, **gradient** means the direction of the change comes from the loss, and **descent** means the mistake keeps getting smaller. >> The path jitters because the observations are random, but its overall tendency is always toward the average.
28|**As the estimate comes down toward the average, the loss comes down too.** With a second list of numbers and the same learning rate, a guess that starts far above the average falls toward it smoothly. The loss, measured as half the squared distance between the guess and the average, drops quickly toward zero at the same time. >> Squaring the distance makes the loss positive whether the guess is too high or too low.
29|**Starting below the average, the estimate rises while the loss still falls.** With the same data and the same learning rate, only the starting guess changes, and now the guess climbs up toward the average instead of falling. >> The distance from the average still shrinks, so the loss still drops toward zero. >> So the direction the guess moves can change, but the learning itself does not, because the mistake always gets smaller.
30|Running the algorithm from a high start, a start near the average and a low start, all three guesses end up at the same average. The **learning rate** decides how they get there. >> With a small learning rate, the guesses creep in slowly and smoothly and settle very precisely. >> With a large learning rate, they jump into the right neighborhood almost at once but then keep bouncing around it and never settle down.
31|**Learning faces a fundamental tradeoff between speed and accuracy.** A higher learning rate makes learning faster but less accurate, while a lower learning rate makes it more accurate but slower. >> No single setting gives both, which is frustrating. >> Generations of people have built careers on finding better ways to optimize, so that learning can be both fast and accurate at once.
