3|**The shortest path problem asks for the cheapest way to get from a starting point to an ending point through a network of stages.** Here the start is A, the end is J, and in between are several stages of states, such as B and C, then D, E and F, then G, H and I. Each arrow between two states has a cost, and the total cost of a path is the sum of the costs along it. >> The goal is to find the path from A to J whose total cost is the smallest. >> Problems like this appear everywhere, from finding a driving route to deciding which sequence of sounds best matches a stretch of speech.
4|**The greedy algorithm always takes the cheapest next step without looking ahead.** Starting from A, it picks whichever arrow costs the least, then from that state it again picks the cheapest arrow, and so on until it reaches J. It is very fast, because it only ever compares the few arrows leaving the current state. >> The trouble is that a cheap step early on can lead into a part of the network where a very expensive step waits later. >> So greed is not good here, because the greedy path can end up far from the best one.
5|
6|**The exhaustive algorithm tries every possible path and adds up the cost of each one.** Because it checks everything, it is guaranteed to find the true shortest path, so it is very accurate. >> But when there are many stages and many states, the number of possible paths explodes, so it takes a very long time. >> The paths also overlap, sharing many of the same pieces, so the exhaustive algorithm keeps redoing the same additions over and over.
7|**Dynamic programming starts from Bellman's idea of imagining that part of the problem is already solved.** Suppose the best cost from B to J and the best cost from C to J were already known, and call them the values of B and C. Then the best cost from A to J would simply be the smaller of two sums, the cost of going from A to B plus the value of B, or the cost of going from A to C plus the value of C. >> So the value of a state is the minimum, over all its next states, of the cost to get there plus the value already known at that state.
8|The catch is that the values of B and C are not actually known yet. Bellman's answer is to break a problem into subproblems that can be solved, and if those cannot be solved yet, to break them down further. >> So the big question about A turns into smaller questions about B and C. >> This is the heart of **dynamic programming**, which is solving a problem by decomposing it into smaller problems.
9|The best cost from B to J is not known either, but it could be found if the best costs from D, E and F to J were known. And those could be found from the best costs of G, H and I to J. >> At the last stage, the problem becomes trivial, because the value of G, H or I is just the cost of the single arrow from that state to J. >> So the values are filled in starting at the end and moving backward toward A, one stage at a time.
10|**After all the values are calculated it becomes safe to be greedy.** To find the actual best path, the algorithm starts at A and at each state simply moves to the next state with the best combination of step cost and value. >> The key is to be greedy on the values, not on the raw costs. >> The values already include everything that lies ahead, so following them leads straight along the shortest path.
11|**Dynamic programming gives the algorithm foresight about the future.** In the original problem, a large cost late in the network can trap an early greedy decision that looked cheap at the moment. The values contain the future, because each value already includes every obstacle between that state and the end. >> So decisions made on the values are the best decisions in the present, since the whole future from each state is wrapped up in its value. >> This matches the philosopher's line that life can only be understood backwards but must be lived forwards, since the values are computed backward and then the path is walked forward.
12|**Dynamic programming begins by posing a problem, its subproblems, their subproblems and so on.** The big problem is solved by solving the subproblems, which in turn are solved by solving smaller subproblems. This continues until the problems are trivial to solve. >> Then the solutions are carried back up to solve the bigger problems that contain them, all the way to the original problem.
13|**The values are carried back from each stage to the stage before it by Bellman's idea.** The value at one state is the smallest of a set of numbers, and each of those numbers is the cost to one of the next states plus the value already found at that state. >> Doing this once for each state, from the last stage back to the first, gives every value with no repeated work. >> That is why dynamic programming is far more efficient than the exhaustive algorithm, since each overlapping piece is solved only once and then reused for every path that passes through it.
14|**The best route can require taking a bad step early in order to avoid a much worse step later.** Dynamic programming may choose an expensive first arrow because it leads onto a route that never gets stuck at the costly step further on. It can seem as if planning like that needs a big brain. >> But nature solves the same kind of problem without thinking. >> A lifeguard reaching a swimmer on a uniform beach just runs straight, but when the swimmer is in the water, the fastest route runs farther along the sand, where running is fast, and then cuts into the water, where swimming is slow.
15|**Decision-making turns out to work just like physics.** Light does the same thing as the lifeguard when it passes from air into water, bending so that it takes the path of least time, which is why a pencil in a glass of water looks bent. >> So choosing a bad stretch early to avoid a worse one later is not something only a planning brain does. >> The same principle of finding the best overall path appears in physical systems, in decision-making and in dynamic programming.
16|**Working the values out on the network reveals the best route.** Each state gets written next to it the best cost from there to J, starting with G, H and I and moving back through D, E and F, then B and C, and finally A. >> Once every state has its value, the best route is found by walking forward from A and always stepping to the state that the values point to. >> The route found this way can start with an arrow that greedy would have rejected, because it avoids a costly step later on.

18|**Learning and cooling follow the same kind of curve.** The guess of stochastic gradient descent, starting from very different points, approaches the true average quickly at first and then more and more slowly. A cup of hot coffee cooling down, or iced coffee warming up, approaches room temperature in exactly the same way. >> In both cases the change is fast when the system is far from its goal and slow when it is close. >> So a learning algorithm and a cooling drink are the same kind of dynamical system, each one moving toward an equilibrium.
