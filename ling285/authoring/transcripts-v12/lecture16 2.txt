5|The scatterplot shows every measurement in the vowel data, **525 observations** with **105 tokens of each vowel**. Each dot is one recorded vowel, placed by its **F1** along the horizontal axis and its **F2** along the vertical axis, both in hertz. >> These are exactly the two numbers the network takes in. >> The color of each dot is the correct word for that recording, so the plot pairs every input with its answer. >> All rows of the data file are kept in their original order, and no tokens or outliers were removed. || The five colors match the network’s five outputs. >> Red is **i (dean)**, magenta is **ae (Dan)**, blue is **u (dune)**, cyan is **a (Don)**, and green is **schwa (done)**. >> Each vowel forms a cloud rather than a point, because the same vowel is produced with somewhat different formants from token to token. >> A few dots sit far from their own cloud, such as a green token near 3800 Hz in F2. These stay in the data the network learns from. || Two vowels are easy to pick out. >> The red **i** tokens sit high on the F2 axis, mostly above about 2000 Hz, with a low F1 near 350 Hz. >> The magenta **ae** tokens spread toward high F1 values, out past 800 Hz. >> Where a token falls on one or both axes is enough to set these two apart from most of the others. || The other three vowels overlap heavily. >> Blue **u**, cyan **a** and green **schwa** crowd into the lower middle of the plot, roughly 300 to 800 Hz in F1 and 800 to 1600 Hz in F2. >> A token that lands in that region could belong to any of the three. >> F1 and F2 alone do not separate these vowels cleanly. || This overlap sets a limit for any classifier trained on these data. >> The network sees only F1 and F2, so two tokens at the same place on the plot look identical to it, whatever their true labels. >> No decision rule that uses only these two numbers can label every token correctly. >> The trained networks that follow stay well below perfect accuracy for this reason, among others.

15|The code trains the same five-layer network on the vowel data, starting from one particular set of random weights. **torch.manual_seed(0)** fixes that **initialization**, so the run can be repeated exactly. >> Every layer is **nn.Linear** with **bias=False**, keeping the sizes 2, 3, 2, 4 and 5. >> There are **no activations** between layers, so this is the all-linear network from the forward-propagation example. >> The formants are divided by **1000**, converting hertz to kilohertz so that the input numbers stay small. || The targets and the training loop follow the earlier one-step program, repeated many times. >> **argmax(1)** turns each one-hot target row into the number of its correct class, which is needed to check accuracy. >> The loss is **CrossEntropyLoss**, and the optimizer is plain **SGD** with a **learning rate of 0.1**. >> The loop runs **2,000 epochs**. Each one clears old gradients, computes the loss for all the tokens at once, backpropagates, and takes one step, so each epoch is one **full-batch update**. || After every update, the code measures how many tokens the network labels correctly. >> It runs without tracking gradients, because this check does not train anything. >> For each token, the largest of the five scores is the network’s answer. >> Accuracy is the percentage of tokens where that answer matches the correct class. These are the same **525 training examples**, so the curve is **training accuracy**, not a test on new recordings. || The accuracy curve has a clear shape. >> It starts at about **20%**, the level reached by labeling everything as one of five equally common vowels. >> It stays flat for about the first 200 updates, then climbs quickly into the 40s. >> Near update 390 it drops sharply back toward 20% for a moment, then recovers and settles near 45%. After about 450 updates it barely changes. >> The final training accuracy is **44.95%**, which is **236 of the 525** tokens. || The note under the code explains the source of the curve. >> PyTorch was not available where the plot was made, so the plotted run comes from an equivalent **NumPy** implementation. >> That implementation uses the same network, loss, input scaling, learning rate and number of updates. >> The code gives the PyTorch version of the procedure, and the curve gives the result of running that procedure.
16|The training procedure is run ten separate times, with **seeds 0 through 9**. Each run builds a fresh model and a fresh SGD optimizer, so nothing carries over from one run to the next. >> The only thing that changes from run to run is the **initialization**, the random starting weights. >> The data, the scaling to kilohertz, the loss, the learning rate of 0.1 and the 2,000 full-batch updates are identical in every run. >> There is no shuffling, no random batches and no choice of a best run. || Each colored line is one seed, and all ten begin near **20%** training accuracy. >> They differ in when they leave that starting level. Some climb within the first 100 updates, while others stay flat for 200 updates or more. >> They differ in their early ups and downs. Several drop back toward 20% for a short stretch before recovering. >> They differ in the highest accuracy they reach along the way, which is close to **47%** for some runs. || After the early part of training, the lines come together. >> The fastest runs settle within about 350 updates, and the slowest take about 1,000. >> From then on the curves overlap, and **all ten finish at 44.95%** training accuracy. || The shared final value matters more than the differences along the way. >> Different starting weights send the network down different paths, but every path ends at the same level. >> Trying more seeds, or keeping the best one, would not raise the final accuracy here. >> The limit comes from the network and the data it is given, the same overlapping vowel clouds, not from unlucky starting weights. || The note at the bottom repeats that the curves are executed **NumPy** reference runs. >> NumPy and PyTorch draw different starting weights from the same seed number. >> A PyTorch run with seed 3 would therefore not trace exactly the plotted seed 3 line. >> The overall pattern, varied early paths and one common end point, is what the runs produced.
