5|The scatterplot holds all **525** vowel tokens, **105** of each vowel. Each dot is one recording, placed by its **F1** along the bottom and its **F2** up the side, both in hertz. >> These are the same two numbers the network receives as input. >> The color gives the correct word for that recording, so the plot pairs every input with its answer. || Five colors match the five outputs. >> Red is **i (dean)**, magenta is **ae (Dan)**, blue is **u (dune)**, cyan is **a (Don)**, and green is **schwa (done)**. >> Each vowel forms a cloud, because the same vowel comes out with different formants on different tokens. >> No tokens were removed, so a few stray dots sit far from their clouds. || Two vowels stand apart. >> Red **i** sits high on F2, mostly above about 2000 Hz, with a low F1. >> Magenta **ae** spreads out toward high F1, past 800 Hz. || Three vowels overlap. >> Blue **u**, cyan **a** and green **schwa** crowd together in the lower middle, roughly 300 to 800 Hz in F1 and 800 to 1600 Hz in F2. >> A token in that region could belong to any of the three. || The overlap limits any classifier that sees only F1 and F2. >> Tokens that land in the same spot look identical to the network, whatever their label. >> No rule based on these two numbers can label all of them correctly, which is why the trained networks stay well below perfect.

15|The code trains the **2 to 3 to 2 to 4 to 5** network on the vowel data, starting from one random **initialization** fixed by **torch.manual_seed(0)**. >> Every layer is **nn.Linear** with **bias=False**, and no activations sit between layers, so this is the all-linear network. >> The formants are divided by **1000**, turning hertz into kilohertz and keeping the inputs small. >> **argmax(1)** turns each one-hot target row into the number of its correct class. || Training uses **CrossEntropyLoss** and plain **SGD** with a **learning rate of 0.1** for **2,000 epochs**. >> Each epoch clears old gradients, computes the loss on all the tokens together, backpropagates and takes one step. >> So every epoch is one **full-batch update**. || After each update the code measures accuracy without tracking gradients. >> The network’s answer for a token is its largest score. >> Accuracy is the percentage of tokens where that answer is the correct class. >> The tokens are the same **525** used for training, so this is **training accuracy**. || The curve starts at about **20%**, the level for one of five equally common vowels. >> It stays flat for about 200 updates, then climbs into the 40s. >> Near update 390 it drops sharply toward 20% for a moment, then recovers. >> After about 450 updates it barely moves, ending at **44.95%**, which is 236 of 525 tokens. || The plotted run comes from an equivalent **NumPy** program. >> PyTorch was unavailable where the curve was made, so the same network, loss, scaling and updates were run in NumPy. >> The code gives the PyTorch version of the procedure, and the curve gives the result of running it.
16|The same training runs ten times, with **seeds 0 through 9**. >> Each run builds a fresh model and a fresh SGD optimizer. >> Only the **initialization**, the random starting weights, changes from run to run. >> Data, scaling, loss, learning rate and the 2,000 full-batch updates stay identical. || Each colored line is one seed, and all ten start near **20%**. >> Some leave 20% within the first 100 updates, and others stay flat for 200 or more. >> Some drop back toward 20% for a short time before recovering. >> The highest accuracy along the way is close to **47%** in some runs. || The lines then come together. >> The fastest runs settle within about 350 updates, and the slowest take about 1,000. >> After that the curves overlap, and **all ten finish at 44.95%**. || Different starting weights take different paths but reach the same end. >> Trying more seeds or picking the best one would not raise the final accuracy here. >> The limit comes from the network and the overlapping vowel data, not from unlucky starting weights. || The curves are executed **NumPy** reference runs. >> Matching seed numbers in NumPy and PyTorch do not give matching starting weights. >> A PyTorch run with the same seed would not trace exactly the same line, but the pattern of varied paths and a shared end point is what the runs produced.
