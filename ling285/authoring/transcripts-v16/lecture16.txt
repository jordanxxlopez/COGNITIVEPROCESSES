5|Every vowel in the data appears here, **525** tokens in all, **105** of each. Each dot sits at its **F1** along the bottom and its **F2** up the side, in hertz. >> These are the two numbers the network gets, and the color tells you the right word. >> So the plot puts every input next to its answer. || The colors line up with the network’s five outputs. >> Red is **i (dean)**, magenta **ae (Dan)**, blue **u (dune)**, cyan **a (Don)**, and green **schwa (done)**. >> Each vowel spreads into a cloud, because no two tokens of a vowel come out with exactly the same formants. >> Nothing was thrown out, so a few strays sit far from home. || A couple of vowels are easy to spot. >> Red **i** floats high on F2, mostly above about 2000 Hz. >> Magenta **ae** stretches out along F1, past 800 Hz. || The other three pile on top of each other. >> Blue **u**, cyan **a** and green **schwa** all crowd into the lower middle, roughly 300 to 800 Hz in F1 and 800 to 1600 Hz in F2. >> A dot in that crowd could be any of the three. || That pile-up is a hard limit for the network. >> It only ever sees F1 and F2, so two tokens in the same spot look exactly alike to it. >> Whatever rule it learns from these two numbers, some tokens will land on the wrong side, and accuracy stays well short of perfect.

15|The same five-layer vowel network now trains for real, starting from one set of random weights picked by **torch.manual_seed(0)**. >> All four **nn.Linear** layers use **bias=False**, and nothing sits between them, so the network stays all linear. >> Dividing the formants by **1000** turns hertz into kilohertz and keeps the inputs small. >> **argmax(1)** turns each one-hot target into the number of its right answer. || Training runs **2,000 epochs** of **CrossEntropyLoss** and plain **SGD** at **learning rate 0.1**. >> Every epoch clears the old gradients, scores all the tokens at once, backpropagates and takes one step. >> That makes each epoch a single **full-batch update**. || After every step the code counts how many tokens the network gets right. >> Its answer for a token is whichever of the five scores is biggest. >> The count uses the same **525** tokens it trains on, so it is **training accuracy**. || The curve sits at **20%**, the one-in-five level, for about the first 200 updates. >> Then it shoots up into the 40s. >> Near update 390 it suddenly falls back toward 20% and bounces right back. >> By about 450 updates it has flattened out, and it finishes at **44.95%**, 236 of 525 tokens. || One more detail matters for reading the curve. >> PyTorch wasn’t available where the plot was made, so the line comes from a **NumPy** program that runs the same network, loss, scaling and updates.
16|Now the whole training run happens ten times, with **seeds 0 through 9**. >> Every run gets a brand-new model and optimizer. >> The only difference is the **initialization**, the random weights the network starts with. || All ten lines begin near **20%**, and then they go their own ways. >> Some take off within the first 100 updates, and others sit flat for 200 or more. >> A few fall back toward 20% for a while before recovering, and the best moments come close to **47%**. || Eventually they all find each other. >> The quickest settle down by about 350 updates, and the slowest take about 1,000. >> After that the lines lie on top of one another, and **all ten finish at 44.95%**. || So where the network starts changes its journey but not where it ends up. >> Running more seeds or keeping the luckiest one would not push the final accuracy higher. >> The ceiling comes from the network and the tangled vowel clouds, not from bad starting weights. || These are executed **NumPy** runs. >> The same seed number gives different starting weights in NumPy and PyTorch, so a PyTorch seed 3 would wander a little differently while ending the same way.
