2|Picture the vowel network as a set of columns. On the left are two inputs, **F1** and **F2**. On the right are five outputs, one for each word, **done, dune, dean, Don** and **Dan**. >> The inputs hold measurements of the sound, in hertz. >> The outputs hold the network’s response to each word. >> They look alike as circles, but they do very different jobs. || In between are three **hidden layers**, with **three, two and four** neurons. >> Reading across, the shape is **2 to 3 to 2 to 4 to 5**. >> Those numbers count neurons in each layer, not recordings or training rounds. >> Each hidden neuron collects values from the layer before it and passes its own result along. || Every layer is **fully connected** to the next, so each neuron is wired to every neuron that follows. >> Each wire has its own **weight**, and all **40** of them are signed numbers, from tiny ones like **+0.005** and **−0.001** near the inputs to larger ones like **+0.6** and **−0.4** farther in. >> A positive weight passes its contribution along as it is, while a negative weight flips its sign. || Notice that F1 feeds all three first-layer neurons, and so does F2. >> Each of those six wires has a different weight. >> So each first-layer neuron mixes the same two formants in its own proportions. || The weights stay put in this picture. >> A different formant value changes what travels along the wires. >> A different weight changes how much a wire counts. >> Either way, a weight is just one wire’s contribution, never the probability of a word.
3|**Forward propagation** sends the input through the network one layer at a time. The example is **F1 = 320** and **F2 = 2000**. || Start with the top neuron of the first hidden layer. >> It computes **w₁ times F1 plus w₂ times F2**. >> Its weights are **+0.005** and **−0.001**, so F1 adds a small positive amount and F2 adds a larger negative amount. >> The total comes to **−0.40**. || That multiply-and-add is called an **inner product**. >> The other two first-layer neurons do the same thing with their own weights and land on **6.64** and **2.72**. >> A negative result is still a perfectly good value for the next layer to use. || Every later layer repeats the same trick on the layer before it. >> The second layer comes out near **5.50** and **−5.93**. >> The third comes out near **1.57, −1.95, −1.95** and **−2.88**. >> The layers have to go in order, since each one needs the finished values of the one before. || The five last sums are **logits**, which are scores and not yet probabilities, **0.622, −1.398, −1.300, −0.478** and **−1.076**. >> **Softmax** turns them into probabilities by raising e to each logit and dividing by the total of all five. >> Every probability comes out positive, and together they add to 1. || **Done** wins with about **55.7%**, while **dean** gets only about **8.1%**. >> Don, Dan and dune land at about 18.5%, 10.2% and 7.4%. >> These are just the network’s current guesses, made with linear hidden activations and fixed weights, not the word that was actually spoken.

6|Training starts by holding up the network’s answer next to the right answer. That comparison drives **backpropagation**. >> The **computed output** says **done** at **55.7%** and **dean** at just **8.1%**. >> The **desired output** puts a **1** on **dean** and **0** everywhere else, because dean is the word that was spoken. >> So the network’s favorite and the right answer disagree. || **Cross-entropy loss** puts a number on how wrong the network is, using the probability it gave the true word. >> Here the loss is the negative log of the probability of dean. >> Push more probability onto dean and the loss drops, and take probability away and the loss climbs. || Then the calculation runs **backward**, from the outputs toward the inputs. >> First it works out how the final layer of weights contributed. >> It uses that to work out hidden layer 3, then hidden layer 2, then hidden layer 1. >> At each step, the layer’s weights are replaced with new ones, so **+0.1** becomes **+0.083** and **+0.6** becomes **+0.622**, for instance. || A **gradient** tells how the loss would change if one weight changed a little. >> The update takes the old weight and subtracts the learning rate, **η**, times the gradient. >> A positive gradient pulls the weight down, and a negative one pushes it up. || The activations from the forward pass are frozen while all of this happens. >> Every gradient uses the original weights, so the updates are really one step taken all at once. >> To see the improved predictions, a new forward pass is needed. >> The input wires get a much smaller learning rate, because their inputs are raw hertz values, which are large numbers.
7|Here is the question. **If we increase this w, will the error go up or down?** The right word is **dean**, but the network is betting on **done**. So the real question is what the change does to dean’s probability. || Take the **pink** connection first. It runs from the top neuron of the last hidden layer straight to **done**. >> The weight is positive, and the neuron feeding it sits at about **1.57**. >> Turn the weight up and done’s score goes up. >> Since softmax splits one fixed total among five words, a stronger done means a weaker dean, and the error goes **up**. So this weight should come down. || Now the **blue** connection. It runs from **F1** to the top neuron of the first hidden layer. >> Turn it up and that neuron’s value goes up, because F1 is positive. >> But from there the change ripples through layer after layer of positive and negative wires before reaching all five outputs. >> The sign of this one early wire cannot tell, by itself, which way the error will move. || The full backward calculation settles it. >> For this network and the dean target, the blue wire’s gradient is positive too. >> Turning it up would raise the error, so the update turns it down. >> Both marked weights end up shrinking. The late one can almost be read off the output, but the early one needed every downstream path added together, and adding those paths up is exactly what backpropagation does.
8|Why does training run **backward**? Compare fixing the **last** weights with fixing the **first** weights. || The **last weights, W5**, set the output probabilities directly. >> The error depends on them very directly. >> The gap between what the network said and what it should have said points straight to better W5 values. || The **first weights, W2**, are a much harder case. >> They shape the first hidden layer, which then passes through two more layers and many other weights before anything reaches the output. >> Figuring out how much W2 is to blame for a mistake at the very end is really hard. >> On top of that, the effect of W2 on the error **includes** the effect of W5, because W5 sits downstream. || So **W5 is the easy problem**, and the W2 problem has the W5 problem buried inside it. >> The natural plan is to solve the small problems first and reuse those answers for the bigger ones. >> That plan is **dynamic programming**, and **backpropagation is Bellman–Viterbi dynamic programming**. >> It works out the effects near the output once, stores them, and hands them back as it moves to each earlier layer, instead of redoing all the downstream work for every early weight. || The punchline is **backpropagation = SGD + dynamic programming**. >> **SGD**, stochastic gradient descent, is the rule that nudges each weight downhill on the error. >> Backpropagation hands SGD the gradients it needs, and dynamic programming is what makes that fast.
9|To learn, the network needs examples with their answers attached. These live in two **training matrices**. || The first is **Formant_Inputs**, **110 × 2**. >> Each of its 110 rows holds one recording’s **F1** and **F2** in hertz. >> The two columns are the two measurements, and each row is one example. || The second is **TrueVowel_Outputs**, **110 × 5**. >> Its columns are **done, dune, dean, Don** and **Dan**. >> Each row puts a **1** under the right word and a **0** under the other four. That is a **one-hot** target. || A few sample rows make the pairing concrete. >> **500 and 1500** go with **done**, and **350 and 1000** go with **dune**. >> **320 and 2000** go with **dean**, the same example that has been running through the network. >> **700 and 1100** go with **Don**, and **800 and 1700** go with **Dan**. >> These rows show the layout. The full matrices hold all 110 recordings. || The two matrices have to stay lined up, row for row. >> The third input row, 320 and 2000, belongs with the third target row, dean. >> Shuffle one matrix without the other and the sounds get paired with the wrong answers. >> Matching row counts are not enough. The order has to match too. || Keep the network’s guess separate from the target. >> Before training, the network favors **done**, at 55.7%, for the dean recording. >> The target still says dean. Training compares the two and never swaps the right answer for the network’s guess.
10|One full training step fits in a short **PyTorch** program, and it uses all 110 recordings at once, a **full-batch** step. || The data come first. >> **X = torch.load("Formant_Inputs.pt").float()** loads the **110 × 2** formants. >> **Y = torch.load("TrueVowel_Outputs.pt").float()** loads the **110 × 5** targets. >> **.float()** makes them floating-point numbers. The program expects those files to exist already. || Next comes the network, built with **nn.Sequential**. >> **nn.Linear(2, 3)**, **nn.Linear(3, 2)**, **nn.Linear(2, 4)** and **nn.Linear(4, 5)** give the familiar **2 to 3 to 2 to 4 to 5** shape. >> No sigmoid appears between them. || Then five lines do the training step. >> **sgd = torch.optim.SGD(net.parameters(), lr=0.1)** sets up stochastic gradient descent with a **learning rate of 0.1**. >> **sgd.zero_grad()** wipes out any old gradients. >> **loss = nn.CrossEntropyLoss()(net(X), Y)** runs the network on all of X and scores it against Y, doing the softmax-related work inside the loss, so the last layer just hands over logits. >> **loss.backward()** works out every gradient. >> **sgd.step()** actually changes the weights. || Each line has its own job. >> Working out a gradient does not move a weight. Only the step does. >> Wiping gradients does not erase anything the network has learned. || All **110 rows** feed this one step, and there is no loop repeating it. >> The program starts from PyTorch’s own default weights and biases, so it shares the drawing’s layer sizes but not its particular numbers.
11|The **sigmoid activation function** is **σ(z) = 1 / (1 + exp(−z))**. Feed it any inner product z and it hands back a number between 0 and 1. || At the extremes, it pins the answer near a limit. >> When the inner product is **large and positive**, the sigmoid sits **near 1**. >> When it is **large and negative**, the sigmoid is **basically 0**. >> At an inner product of **−4**, **σ(−4) = 0.0180**, and at **4**, **σ(4) = 0.9820**. || Drawn out, the function is an S. >> Along the bottom runs the **linear activation**, the weighted sum, and up the side runs the **sigmoid activation**. >> The S climbs steeply in the middle and goes almost flat at both ends. >> Out on the flat parts, even big changes in the input barely move the output. Near the middle, small changes move it a lot. || The formula explains why. >> A big positive z makes exp(−z) tiny, so the fraction approaches 1. >> A big negative z makes exp(−z) enormous, so the fraction shrinks toward 0. || **Lord Edgar Adrian**, winner of the **Nobel Prize in Physiology or Medicine in 1932**, gives the biological motivation. >> **Neurons are nearly digital**, on or off, roughly. >> Adrian studied how often nerve fibers fire, so the sigmoid captures a graded response that behaves almost like a switch at its ends. || The same shape shows up in **animal perception**. >> Some things that seem alike are perceived as different, and some things that are very different are perceived as the same. >> Two inputs on opposite sides of the steep middle come out far apart, while two very different inputs out on one flat end come out nearly the same.
12|Now sigmoid gets switched on **one neuron at a time**. The input stays **F1 = 320** and **F2 = 2000**, and not a single weight changes. >> **Purple** neurons are still linear. >> **Green** neurons run their inner product through sigmoid. >> The nine hidden neurons switch over in layer order, the first three, then the next two, then the last four. || The very first switch moves the top first-layer neuron from **−0.400** to about **0.401**. >> That one change alters what every neuron in the next layer receives. >> So everything downstream is **recalculated**, all the way out to the probabilities. >> This builds a real sigmoid network one piece at a time. Slapping sigmoid onto the old stored numbers would not give the same thing. || Once the whole first layer uses sigmoid, its outputs are about **0.401, 0.999** and **0.938**. >> Feeding those into the second layer and squashing gives about **0.713** and **0.223**. >> The third layer finishes near **0.599, 0.609, 0.609** and **0.481**. || The outputs still go through **softmax**. >> With every hidden neuron on sigmoid, **Dan** takes the lead at about **32.0%**. >> **Dean** climbs to about **23.0%**, and **done** falls all the way to about 16.2%. >> Same input, same weights, and yet a completely different pattern of guesses. || None of this is training. >> Dean’s share rose from 8.1%, but Dan still beats it. >> So changing the activation rule can change which word the network favors without the network having learned the right answer.
13|The PyTorch program for the sigmoid network is the earlier program with sigmoid slipped in after each hidden layer. >> It still loads **X**, the **110 × 2** formants, and **Y**, the **110 × 5** targets. >> **nn.Sigmoid()** now follows **nn.Linear(2, 3)**, **nn.Linear(3, 2)** and **nn.Linear(2, 4)**. >> Each hidden layer adds up its inputs and then squashes the sums before passing them on. || Sigmoid reshapes values but never changes how many there are. >> Three values going in are three values coming out, so **nn.Linear(3, 2)** still gets exactly the size it expects. >> The same goes for the two-value and four-value layers, so the shape stays **2 to 3 to 2 to 4 to 5**. || The last layer, **nn.Linear(4, 5)**, gets no sigmoid. >> Its five logits go straight to **CrossEntropyLoss**, which does the softmax-related work itself. >> The hidden sigmoids and the final word probabilities have separate jobs, and no hidden neuron turns into one of the five words. || The training lines do not change at all. >> **zero_grad**, the forward pass and its loss, **backward**, then **step**. >> The learning rate is still **0.1**, and all 110 recordings feed the one step. || The drawing and the code start from different places. >> The drawing uses the original illustrative weights with no biases, which is how Dan gets **32.0%** and dean **23.0%**. >> The code starts from PyTorch’s defaults, so it copies the structure, and only the same starting weights and bias choices would copy those exact numbers.
