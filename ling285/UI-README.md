# LING285 interface

This is a standalone static Study Studio. Serve the repository with any static HTTP server and open `/ling285/`. No package installation or build is needed. The interface fetches `data.json` and preserves personal state under `ling285-study-studio-v1` without reading another course's progress.

Every collection owns its numbered source sections. A section's stable `id` carries its notes, read mark, and open preference across collection, combined, core, guide, and visual-reader views. Written practice uses stable question IDs for drafts, revealed model answers, and self-ratings. “Ready” clears a written self-rating from the review queue; “Partial,” “Review,” and “Uncertain” add it. A separate uncertainty flag keeps any question in review until cleared. Revealing an answer never grades a draft.

The current mixed set samples up to 20 questions without replacement within the active module. Mixed, multiple-choice, and written formats are available for current tests and lecture quizzes. Sampling covers available lectures and formats before weighting the remaining choices by study relevance. Lecture sets use questions assigned to the active module that cite the selected lecture. Later editions can replace the active bank while preserving IDs for unchanged material. Unknown or retired IDs are filtered when progress loads. Written explanations remain self-assessed.

Module II is the default workspace. Module I contains Lectures 01–10, its own review tools, and the Meadows readings. Sources & coverage retains every original and the teaching for supporting documents hidden from the numbered lecture navigation. Module membership uses explicit question assignments, so integrated questions requiring Lectures 11–13 do not appear in Module I merely because they cite an earlier background source.

MCQ selections and submitted answers use stable option IDs. Shuffled option order is saved separately and retained across reloads, so a selected letter never changes the underlying answer. Checking an answer reveals feedback for every option. Incorrect answers and flagged questions enter the module's retry queue. Progress backups include MCQ state and module sessions alongside existing notes and written drafts. Revealing a written model answer never counts as automatic correctness.

The data contract is `data.json` with `course`, `modules`, `collections`, `questions`, `guide`, `coverage`, and `assessmentModel`. Questions have `type` (`written` or `mcq`), `moduleId`, and positive `priority`. MCQs add four `options` with stable `id`, `text`, and `feedback`, plus `correctOption`. Guides have `moduleIds`. Optional guide `kind` values `experiment`, `demonstration`, or `connection` populate the demonstrations view. Source-page references use `{collection, page}`. A section's `assets` may include original images, GIFs, videos, or audio. GIFs and playable media remain prominent; additional static figure images are collapsible. Media downloads start when the relevant player is visible. No service worker or offline-complete claim is made.

Progress can be exported and imported in Sources & coverage. Import checks the course/version and fields, discards unknown IDs, caps file size at 5 MB, and merges personal entries. Storage failures produce a persistent visible warning and leave in-memory entries exportable. Backups are personal browser files, not account synchronization.

Run `node ling285/tests/app-smoke.cjs` from the repository root for browser checks against the current data. Use `--fixture` for an isolated UI fixture without touching course data. The script serves the repository temporarily and uses the installed Chromium/Playwright environment. Checks exercise navigation, original-source viewing, shared notes/read marks, conceptual self-assessment, reload persistence, backups, and mobile containment. A test run verifies interface behavior; it does not establish academic content completeness.
