# LING285 interface

This is a standalone static Study Studio. Serve the repository with any static HTTP server and open `/ling285/`. No package installation or build is needed. The current data contains 26 student collections, 340 source sections, and 292 practice questions. The interface fetches `data.json` and preserves personal state under `ling285-study-studio-v1` without reading another course's progress.

Every collection owns its numbered source sections. A section's stable `id` carries its notes, read mark, and open preference across collection, combined, core, guide, and visual-reader views. Written practice uses stable question IDs for drafts, revealed model answers, and self-ratings. “Ready” clears a written self-rating from the review queue; “Partial,” “Review,” and “Uncertain” add it. A separate uncertainty flag keeps any question in review until cleared. Revealing an answer never grades a draft.

Lectures 11–14 have four parallel transcript editions. Version 1 is the exact original teaching from `data.json`. Version 4 · Teaching notes is selected for new users and loads from `transcripts-v4.json`; Versions 2 and 3 retain their separate files, with explanations organized around intuition and cause and effect. The dropdown changes lecture notes, combined and core notes, source readers, search, recall, print output, and read-aloud together. It preserves the current reader page and uses the same source section IDs for personal notes and read marks.

The selected edition is stored as `transcriptVersion` (`v1`, `v2`, `v3`, or `v4`) in the existing progress record and backups. Older stored progress defaults to Version 4 without losing notes or practice state. Importing an older backup that lacks the new preference keeps the current selection. Module I teaching, original slide text, source visuals, and the complete question bank remain unchanged. Version-file reference PDFs appear separately in Sources & coverage and do not create new lecture collections.

The version file maps each original section ID to its alternative `title` and `teaching` array. Every page of the four affected lectures must be accounted for, including empty teaching arrays for logistics pages. An unavailable or incomplete edition falls back to original teaching with a visible notice rather than presenting partial coverage as complete. Reviewed `visualPresentation[sectionId].hideStaticPreview` flags omit uniform blank slide posters only where original embedded video is available. Those pages lead with the video in either edition; captions, PDF links, teaching, and original figure details remain available. Written content, annotations, and reveal overlays retain their static preview.

Module II currently contains four lecture banks for Lectures 11–14, totaling 200 questions. Its primary current test contains exactly 100 unique questions, with 50 MCQs and 50 written prompts. Each primary lecture quiz contains 50 unique questions, with 25 of each format. Saved format preferences do not shorten these complete sets. Separate optional focused-format and five-question sessions use their clearly labeled available counts. Module I retains its previous 20-question current-test behavior. Written explanations remain self-assessed.

The current test divides each format's places among authoritative lecture owners as evenly as possible, then selects by study relevance within each pool. Complementary remainder allocation keeps overall lecture contributions balanced. With the four supplied lectures, each contributes 25 of the same 100 places. Adding a fifth bank gives each lecture 20 places while retaining the equal format split. Individual lecture banks and progress remain intact. A question's background source references do not count it in another Module II lecture quiz. Later editions preserve IDs for unchanged material; unknown or retired IDs are filtered when progress loads. Earlier short in-progress sets remain resumable and are identified as earlier practice.

Module II is the default workspace. Module I contains Lectures 01–10, its own review tools, and the Meadows readings. Sources & coverage retains every original and the teaching for supporting documents hidden from the numbered lecture navigation. Module membership uses explicit question assignments, so integrated questions requiring Lectures 11–14 do not appear in Module I merely because they cite an earlier background source.

MCQ selections and submitted answers use stable option IDs. Shuffled option order is saved separately and retained across reloads, so a selected letter never changes the underlying answer. Checking an answer reveals feedback for every option. Incorrect answers and flagged questions enter the module's retry queue. Progress backups include MCQ state and module sessions alongside existing notes and written drafts. Revealing a written model answer never counts as automatic correctness.

The data contract is `data.json` with `course`, `modules`, `collections`, `questions`, `guide`, `coverage`, and `assessmentModel`. Questions have `type` (`written` or `mcq`), `moduleId`, `lectureId` for lecture-owned practice, and positive `priority`. Module II's `assessmentPolicy` records the fixed sizes and format split. MCQs add four `options` with stable `id`, `text`, and `feedback`, plus `correctOption`. Guides have `moduleIds`. Optional guide `kind` values `experiment`, `demonstration`, or `connection` populate the demonstrations view. Source-page references use `{collection, page}`. A section's `assets` may include original images, GIFs, videos, or audio. GIFs and playable media remain prominent; additional static figure images are collapsible. Media downloads start when the relevant player is visible. No service worker or offline-complete claim is made.

Progress can be exported and imported in Sources & coverage. Import checks the course/version and fields, discards unknown IDs, caps file size at 5 MB, and merges personal entries. Storage failures produce a persistent visible warning and leave in-memory entries exportable. Backups are personal browser files, not account synchronization.

Run `node ling285/tests/app-smoke.cjs` from the repository root for browser checks against the current data. Use `--fixture` for an isolated UI fixture without touching course data. The script serves the repository temporarily and uses the installed Chromium/Playwright environment. Checks exercise navigation, original-source viewing, shared notes/read marks, conceptual self-assessment, reload persistence, backups, and mobile containment. A test run verifies interface behavior; it does not establish academic content completeness.

Run `node --test ling285/tests/transcript-versions.test.cjs` to verify edition selection, original teaching preservation, shared progress, reader/search/speech consistency, reviewed video presentation, backup compatibility, and mobile controls. Its optional `--fixture` mode (`node ling285/tests/transcript-versions.test.cjs --fixture`) uses an in-memory UI fixture before final conceptual text is available; it never writes authored material or course data.

## Parallel practice editions

Practice Version 2 loads from `practice-v2.json` and defaults on for Module II. Version 1 retains the original questions in `data.json`; Module I continues using that bank. New IDs distinguish all 200 new questions. `assessmentVersion` selects the practice edition independently of `transcriptVersion`. `practiceSessions` stores attempts under `module2:v1` and `module2:v2`; the legacy `sessions` map retains original-version attempts for compatibility. Both editions' drafts, selections, option orders, ratings, flags, and sessions are included in backups. Switching versions restores that edition's current attempt and review queue. Starting a new attempt retains written drafts while resetting checks for its MCQs, as before.

The original and new questions are registered before stored progress is validated. If Version 2 cannot load, its saved IDs and answers remain dormant and are restored when the file returns. The UI shows the usable original bank and a loading notice. A Version 2 file must contain a complete 25/25 quiz for every Module II lecture; it cannot silently omit a newly added lecture from the current test.

Version 4 is an additional choice in the existing Transcript dropdown. Explicit earlier preferences are preserved. If a selected edition cannot load, the interface falls back to the closest available earlier edition and keeps the requested preference for recovery. Transcript choices remain independent of Practice Versions 1 and 2.
